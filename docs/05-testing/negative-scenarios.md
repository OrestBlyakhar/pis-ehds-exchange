# Негативні сценарії доступу, згоди і порогу

Задача PIS-44. П’ять обов’язкових відмов. Жоден сценарій не має віддати ідентифіковані дані або файл знімка.

## 1. Немає згоди

Лікар закладу-отримувача запитує алергії пацієнта без чинної лікувальної згоди і не обирає аварійний доступ. Очікується: `deny`, у відповіді немає клінічних даних, у журналі є відмова.

## 2. Чужа роль

Дослідник викликає запит лікування. Очікується: `deny`. Лікар відкриває загальний журнал. Очікується: відмова, без записів інших пацієнтів.

## 3. Прострочений дозвіл

Дослідник відкриває дозвіл, у якого дата закінчення вже минула. Очікується: `deny`, новий знімок не будується, повторне завантаження старого файлу не відбувається.

## 4. Мала група

Дозвіл і згоди коректні, але після фільтра когорти лишається менше ніж 5 пацієнтів. Очікується: `denied_small_cell`, файл не створюється, подія є в журналі.

## 5. Читання vault дослідником

Дослідник, який уже отримав знімок, запитує таблицю відповідності псевдонім–пацієнт. Очікується: відмова. Роль, якою відкривається знімок, не читає схему `vault`. Окремий запис журналу фіксує спробу.

Ці сценарії не замінюють прогін демо на живому прототипі.
